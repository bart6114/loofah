# Loofah launch video

Create a distinctive, thoughtfully directed short film that makes one Loofah benefit visible. Bring the judgment of a small animation studio: a memorable visual concept, crafted typography and illustration, expressive motion, and sound planned with the picture. Astra is the directing/coding model; use available editing or rendering tools to produce the actual video. Selecting Astra itself does not render video.

## Establish the assignment

Respect the requested stage: a prompt request needs a usable brief; a script request needs a timed script; a video request needs editable source and a rendered file. For a video, carry work through rendering and visual inspection when tools permit. A storyboard or browser animation alone does not complete a video request.

Infer routine choices and state assumptions briefly. If unspecified, start with a 30-second, 1920×1080, 30 fps English film for prospective Mac users, legible without sound, with one CTA: “Download free for macOS” and `loofah.io`. These are editable production defaults, not platform requirements. Create other sizes or cutdowns according to the distribution brief.

Include a suitable licensed instrumental music bed by default. Legibility without sound is a viewing requirement, not a request for a silent export. Respect an explicit silent brief; if a usable track cannot be obtained, state the limitation and deliver a clearly labeled silent draft rather than silently omitting music.

Identify the audience, one takeaway, launch topic, destination, duration, and available footage. Ask only when missing information materially changes the story or blocks production; continue independent preparation. A feature launch should focus on that feature rather than repeat the whole product pitch.

## Ground the film

Read [brand.md](references/brand.md) for verified styling, assets, and product claim boundaries. This is a repository-owned skill: the Loofah root is three directories above this skill directory. Resolve assets relative to that checkout, including when invoked from another working directory. Refresh relevant source files and visually inspect chosen assets. Current source and user direction take precedence over this snapshot.

Use actual screenshots or recordings for product proof. The homepage contains a styled product illustration; it is not evidence that a particular interaction exists. Use synthetic meeting content for new captures. Never expose private meeting material merely to obtain a demo.

## Direct the story

Read [art-direction.md](references/art-direction.md) before choosing the visual concept. Develop a coherent design and motion language rather than treating the website as a finished video template. Preserve Loofah's recognizable identity while giving the film its own compositions and visual storytelling.

Write a one-sentence takeaway, then a compact shot table with time range, exact on-screen words, visual evidence, movement, and audio if used. Choose an intelligible workflow with a beginning, a useful action, and a visible result. Put the product or a recognizable result in the opening seconds; weave identity into the story instead of delaying it behind a logo bumper.

Give the central payoff enough stillness to read. Use deliberate changes in scale and pacing: a close crop for a useful detail, a wider frame for context, a quiet final CTA. Keep one visual focus per shot. Titles, UI, and camera motion should cooperate. A series of feature cards with identical transitions will feel like a slide deck.

For a request for more character or “oomph,” revise composition, choreography, transitions, and sound together. More decoration, uniformly faster entrances, or a louder track alone does not satisfy that request. Preserve approved messages and useful reading holds while making the movement itself tell the story.

Use plain, specific language. Let real proof carry the claim. Omit invented metrics, superlatives, launch dates, testimonials, and unsupported UI states. Show dependencies honestly when demonstrating generated summaries or time-consuming processing; make editorial time jumps clear.

Suggested timing and a reusable Astra assignment are in [astra-brief.md](references/astra-brief.md). Adapt the structure to the story; do not force every launch into it.

## Produce and finish

Read [production.md](references/production.md) when building or rendering. Reuse an existing video project when available. Otherwise, Remotion is a practical default for precise typography, real UI crops, and repeatable exports. Keep a standalone video project separate from the desktop app's runtime unless the user asks for integration.

Read [music.md](references/music.md) when selecting, editing, mixing, or adding music. Choose the cue to fit the story and Loofah's calm character, preserve its license evidence, and verify that the exported MP4 actually contains the finished soundtrack.

Render representative style frames and a short motion proof of the most important transition before committing to a full export. Inspect actual output and revise weak moments. Then check the finished render for pacing, readable product proof, continuity, clean scene boundaries, correct claims, resolved fonts/assets, and a complete end card. Match verification to the video project; unrelated desktop changes or release workflows are unnecessary.

Deliver the rendered file and editable source with reproducible render instructions. Include subtitles when narration is present, a poster when requested/useful, and asset attribution where needed. State any missing footage, absent audio, illustrative treatment, or verification limit. Do not call an unrendered project a finished video. Creating a video does not authorize publishing or scheduling it.
