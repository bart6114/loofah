The `loof` executable contains both the command-line interface and the MCP server.

## Install with one command

On macOS or Linux, run:

```bash
curl -fsSL https://loofah.io/install.sh | bash
```

The script downloads the latest release binary for your platform, verifies its checksum, and installs it to `~/.local/bin/loof`. It never asks for `sudo`. Set `LOOFAH_INSTALL_DIR` to install somewhere else; the previous `FMTR_INSTALL_DIR` name remains accepted.

:::note
Earlier releases installed `loofah` and `fmtr`. Re-run the installer to add `loof`, then update scripts and MCP configurations. The web installer leaves those old files untouched; remove them after nothing depends on them.
:::

Supported platforms:

- macOS on Apple Silicon and Intel
- Linux on x86_64 and arm64 (glibc 2.35 or newer, such as Ubuntu 22.04, Debian 12, RHEL 9, or later; musl-based distributions such as Alpine are not supported)

:::note
On-device transcription (`loof transcribe`) runs only on Apple Silicon Macs. Every other command and the MCP server work on all supported platforms.
:::

If the install directory is not on `PATH`, the script adds it to your shell profile (`~/.zshrc`, `~/.bashrc`/`~/.bash_profile`, or fish's `config.fish`). Restart your shell afterwards. If your shell still cannot find `loof`, add it manually:

```bash
export PATH="$HOME/.local/bin:$PATH"
```

:::caution
Tarballs downloaded from the GitHub releases page with a browser are not notarized, so macOS Gatekeeper blocks them. Use the install script instead because it is the supported download path.
:::

## Install it from the desktop app

On macOS, open **Settings → Agents** and click **Install**. The app installs the bundled command at `~/.local/bin/loof`, the same path the install script uses, so whichever ran last wins. Both ship the same binary.

:::note
The app uses `loof-dev` and `loof-staging` for development and staging builds, so those channels do not overwrite the stable command.
:::

## Build it from source

You can install the CLI directly from the repository:

```bash
git clone https://github.com/bart6114/loofah.git
cd loofah
cargo install --locked --path apps/cli
loof --version
```

Cargo normally writes commands to `~/.cargo/bin`. Add that directory to `PATH` if needed.

There is no Homebrew formula yet. Windows 11 test installers and bundled CLI binaries are available through the [Windows preview](/windows-preview); the shell installer above remains macOS/Linux only.

## Connect to the vault

Open the desktop app at least once before using the CLI. By default, `loof` looks in Loofah's application-data directory. If you moved the vault in the app, the CLI follows the `vault_path` value in `global.json`.

You can override the path for one command:

```bash
loof --vault-path /path/to/vault --json sessions list
```

Or set it in the environment:

```bash
LOOFAH_VAULT_PATH=/path/to/vault loof --json sessions list
```

`--base /path/to/vault` is an older equivalent, but `--vault-path` is clearer and takes precedence when both are present.

The CLI reads and writes the vault: `loof sessions new`, `loof import`, and `loof sessions note --set` create and edit meeting data in the same format the desktop app writes, and `loof transcribe` replaces a meeting's transcript. The MCP server stays read-only. See the [CLI reference](/reference/cli) for every command.
