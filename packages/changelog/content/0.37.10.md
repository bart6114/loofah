<banner title="Update every device sharing your vault" variant="warning">
Quit older Loofah versions on every device sharing a vault, then update all of
them before opening the vault with this version. On first startup, Loofah moves
note folders to permanent locations based on their existing IDs. Older versions
would rename those folders back. Bookmarks to the old folder paths may need
updating; session IDs and links to attachments inside notes stay valid.
</banner>

## Changes

- Notes now stay in `sessions/<id>/`. Changing a title or date, including an
  automatically generated title, no longer renames the folder.
- Existing note folders are moved whole during desktop startup, preserving
  notes, transcripts, recordings, summaries, tasks, and attachments. If a folder
  cannot be moved because of a conflict or unreadable metadata, Loofah leaves it
  untouched and shows its path and the reason. Other notes remain available;
  resolve the issue and restart Loofah to retry.
- Removed the timeline action that renamed a note's folder to match its title.

## Fixes

- Opening a note or its recording no longer requires searching other note
  folders, reducing unnecessary vault reads.
- Search and related-tag updates wait for the vault to finish opening, and
  repeated background failures use bounded retries.
- Recording works without a configured transcription model and no longer
  attempts an implicit cloud transcription connection when configuration is
  missing. Audio is kept locally for later transcription.
- Audio and attachment views refresh after file changes, deletion, and restore
  in both the main window and standalone note windows.
- Rapidly stopping and resuming a recording keeps the vault protected from
  relocation until recording and finalization finish.
